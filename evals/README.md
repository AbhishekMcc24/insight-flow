# Insight Flow AI evals

Measures how often the Analyst agent answers business questions **correctly**, per provider. Each question in
[`questions.yaml`](InsightFlow.Evals/questions.yaml) is answered by the agent over the deterministic retail dataset
(5,000 rows, generated by `RetailDataGenerator`). The agent's last successful SQL is re-executed in the sandbox, and its
**result set** is compared with the result of the question's reviewed `expected_sql`. The comparison matches columns by
value (names and extra columns don't matter) with a numeric tolerance, and is ordered or unordered per question.

## Run

```bash
dotnet run --project evals/InsightFlow.Evals -- --provider reference
```

`reference` replays the expected SQL (no model, no keys). It must score 20/20, and it also checks that a deliberately
wrong answer fails. Run it after editing questions or the scorer.

```bash
dotnet run --project evals/InsightFlow.Evals -- --provider anthropic
```

```bash
dotnet run --project evals/InsightFlow.Evals -- --provider azure-openai --limit 5
```

- Credentials: `ANTHROPIC_API_KEY`; or `AZURE_OPENAI_ENDPOINT` + `AZURE_OPENAI_API_KEY` (or `AZURE_OPENAI_USE_ENTRA_ID=true`),
  optionally `AZURE_OPENAI_DEPLOYMENT_LARGE`. User-secrets of the evals project work too (`Ai:Anthropic:ApiKey`, …).
- Every task is routed to the chosen provider's `large` model, so a report measures exactly one provider/model.
- Reports go to `eval-results/` (git-ignored) as Markdown and JSON. In CI: Actions → **AI evals** → Run workflow.

## Adding a question

Append an entry with a new id (never renumber). Write `expected_sql` against table `input`, set `ordered: true` for
rankings/time series and a `tolerance` for percentages, then run `--provider reference` to confirm it passes.
